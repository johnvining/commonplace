Why ~/Library/Caches/org.swift.swiftpm points into this folder
================================================================

SwiftPM writes manifest diagnostics to ~/Library/Caches/org.swift.swiftpm.
There is no flag or environment variable to move that path (checked
against Xcode 27.2's SwiftPM and xcodebuild). Muse's sandbox can
only write inside this project, so xcodebuild fails there with
"cannot open file .../ManifestLoading/ios.dia (Operation not permitted)".

Fix applied once, from a normal terminal (not inside Muse):

  mv ~/Library/Caches/org.swift.swiftpm ~/Library/Caches/org.swift.swiftpm.backup
  ln -s /Users/johnvining/Documents/GitHub/commonplace/ios/.swiftpm-cache \
        ~/Library/Caches/org.swift.swiftpm

Effect: the shared SwiftPM cache for all projects physically lives in
ios/.swiftpm-cache (ignored by git). Contents are pure cache and
regenerate if deleted. Xcode and swift builds keep working.

Undo:

  rm ~/Library/Caches/org.swift.swiftpm
  mv ~/Library/Caches/org.swift.swiftpm.backup ~/Library/Caches/org.swift.swiftpm

(or skip the second line; the cache recreates itself empty.)
