# Known Issues

- **Entity-notes endpoints silently truncate at 500.** `reqGetNotesFor{Author,Idea,Pile,Work}` and `reqGetAllNotesForAuthor` cap responses at 500 notes (commit 127b2d6). Server already accepts `?skip=&limit=`, but the client has no paged UI — entities with more than 500 notes show only the most-recently-updated 500, with no indication more exist. Fix: add a "load more" / paged UI on the client, or return a count + `hasMore` flag from the endpoint and surface it.

- **Audit other places where the pill input would fit.** The `PillInput`-style component (`AuthorsChipList` / `IdeasPillList` / `PilesPillList`) is now the pattern for multi-select autocomplete: chips + inline input + dropdown of suggestions + Backspace/× to remove. Used on authors (Note, Work), ideas (Note), piles (Note, Work). Other autocomplete usages haven't been audited — sweep `grep -nE "Autocomplete\b" site/` and review each remaining call site. Likely candidates: anywhere the user currently picks multiple of something via the legacy `Autocomplete` + chip-row pattern. Single-select autocomplete (Work field on a Note, search bar) does NOT need this — keep those as-is. Also: extract the three pill-list components into a shared `PillInput<T>` to remove the ~80% duplication.

- **Work rows on entity pages don't show piles or note count.** The `<ResultWork>` rows shown on Author pages (and anywhere else works are listed — Pile pages, search results, etc.) currently show only the work's name, year, and authors. Should also show: (1) the work's piles as chips (using the same `Prefix: Name` rendering as `PileLabel`), and (2) the note count (`note_count` is already returned by `findWorksByString` via the with-counts aggregate — wire that into the row). For Author specifically: extend the controller (`reqGetWorksForAuthor`) to populate piles and to either compute note_count via aggregate or join from notes. Same display change in `ResultWork.tsx` so it applies to every caller.

- **Works don't support ideas yet.** GitHub issue #216. Notes have an `ideas: [ObjectId]` field that powers the multi-select idea picker on notes, but Works don't have an equivalent. Adding it would: (1) add `ideas: [ObjectId]` to `server/src/resources/work/work.model.ts` with an index; (2) include it in `WORK_WRITABLE`; (3) update `defaultControllers.updateOne` flow (already handles via the whitelist); (4) on the frontend, drop `IdeasPillList` into `Work.tsx`'s edit form the same way it sits on `Note.tsx`; (5) propagate idea info into work display so authors-page / pile-page rendering can show idea chips on works too. Aggregation on `recentIdeas` already uses `$unwind` so swapping in Work for additional counts is straightforward. Migration: `db.works.updateMany({ ideas: { $exists: false } }, { $set: { ideas: [] } })`.

- **`cplace` CLI lacks "show contents of entity" commands.** Today's `cp piles <query>` / `cp authors <query>` / `cp ideas <query>` / `cp works <query>` only run the autocomplete — they list entities matching the query, not what's *inside* them. Need an additional command (e.g. `cp pile show <id-or-nick>`) that calls the existing server endpoints — `GET /api/pile/:id/notes`, `/api/pile/:id/works`, `/api/auth/:id/notes`, `/api/auth/:id/all-notes`, `/api/auth/:id/works`, `/api/idea/:id/notes`, `/api/work/:id/notes` — and prints the result. Same shape needed for every entity type that contains notes/works.

## Small bugs & improvements (from GitHub)

Triaged on review of all 46 open issues. Listed by number, low-hanging fruit only — larger features (timeline #187, mobile styling #108, AI features #329/#330/#331, merge auth+ideas #313, kindle import #64, etc.) are out of scope for this list.

- **#47 — Tab order broken with multiple NoteLists on a page.** Focus management bug. Each NoteList increments tabIndex from 1, so multiple lists collide. Fix: scope tabIndex inside each list, or use a shared counter via context.
- **#51 — Add validation to Mongo.** Broad — start small: `required: true` on schema fields where it's known (note.title is intentionally optional, but work.name, idea.name, pile.name, auth.name should reject empty strings). Tighten as gaps are found.
- **#101 — Delete images when deleting a note.** Cascade isn't complete. The note doc is deleted but the files in `image-store/<noteId>/` stay. Add an `fs.rm` in the cascade-delete chain for the note resource.
- **#102 — Fix year regex in Safari.** Probably a lookbehind/lookahead used in `guessYearFromUrl` that Safari's older versions don't support. Test in Safari and rewrite with simpler grouping if needed.
- **#223 — Close Mongo connection after CLI run.** The `cli/import.ts` etc. leave the mongoose connection open after running, so the process hangs. Add `mongoose.disconnect()` at the end of each CLI entrypoint.
- **#233 — Consolidate update framework on auth/pile/work/idea.** Each entity has its own `handleAcceptUpdates` + pending state. Extract a shared helper (`useEntityEditState<T>(entity, writableFields)`) so the four pages stop drifting apart.
- **#255 — Show exact tag if it exists when too many results.** Autocomplete elsewhere returns top N matches; if the exact-typed string matches a real entity that fell off the list, surface it explicitly at the top.
- **#298 / #302 — Standardize note-button component & move existing usages.** A lot of ad-hoc `<button className="...">` calls. Extract a `NoteButton` (matching the existing `TopLevelStandardButton` shape) and sweep call sites.
- **#299 — Support uploading multiple images at once.** The existing `<ImageUploader allowMultiple={true} />` already handles this for the Work toolbar; some other call sites still pass `allowMultiple={false}`. Audit and flip where it makes sense.
- **#304 — Disable password managers on fields.** Add `autoComplete="off"` (and arguably `data-1p-ignore` / `data-lpignore="true"`) on inputs that don't want autofill. Most notably the autocomplete pickers for ideas / piles / authors / works.
- **#307 — Enter in search bar defaults to search.** Today Enter on the search bar selects the first autocomplete suggestion. If nothing's highlighted (or after Esc), Enter should run a search instead of doing nothing.
- **#308 — Nick doesn't work for non-notes via URL.** `/n12345` resolves to a note nick, but `/w12345` / `/i12345` / `/p12345` don't have the same URL routing. Add routes that look up by nick prefix.
- **#310 — Auto-focus first note in a list.** When a list mounts (or shrinks to one), focus should land on that note so keyboard nav works without an extra Tab. Currently focus stays on the search bar / nothing.
- **#311 — Outline color when editing ideas/piles on note-full.** Change the note-full border to `$semantic_idea` (blue) when `edit_ideas` is active and `$semantic_pile` (purple) when `edit_piles` is. Visual signal of which mode you're in.
- **#312 — Ctrl-E opens edit for work on the work page.** Wire `Ctrl-E` in the `ENTITY_PAGE` scope on Work.tsx to toggle the work editor — the keyboard hook (`useEntityKeyboardShortcuts`) already exists, just hook in.
- **#314 — Search results show a snippet of the matched note.** Partially done: `NoteResult` already renders body/title snippets with highlight. Remaining: ensure all blank-bodied notes still show *something* (title, citation, ideas) rather than an empty result row.
- **#315 — Show birth/death (auth) and start/end (idea) in autocomplete results.** The autocomplete dropdown row currently just shows the name. Append the years (`Tyler Cowen (b. 1962)` / `Cold War (1947–1991)`) for disambiguation.
- **#316 — Editing idea on a note: Ctrl-S overwrites title with suggestion.** Keyboard shortcut scope leak. `Ctrl-S` is "Suggest title/ideas" in NOTE_EDIT scope; when an idea autocomplete is focused it should take precedence (AUTOCOMPLETE scope) and not bubble to the title-suggest handler.
- **#318 — Put nick number in browser tab title.** `<title>` currently shows the note title. Append the nick (`n12345 — My Note`) so bookmark/tab search picks up the nick token.
- **#322 — Remove trailing space from suggested OpenAI title.** One-line trim in `reqGetSuggestionForNoteTitle` (or wherever the OpenAI response is shaped). Probably `.trim()` after `.replace(/^["']|["']$/g, '')`.
- **#325 — Sort linked notes by `updatedAt`.** Linked-notes list currently uses insertion order, so the order shifts every time you re-render. Add `sort({ updatedAt: -1 })` in the linked-notes fetch.
- **#327 — Resolve Express callback TODO in server.ts.** There's a `// TODO: Callback function` next to the `app.all('*', reqAuthenticate)` line. The Express docs explain — likely just rewrite with the modern middleware signature.
- **#328 — Remove unneeded ngrok React code.** Dead code from when ngrok was integrated client-side. Now ngrok is a separate docker-compose service — none of the React code paths should reference it. Grep for "ngrok" in `site/` and delete what's unused.
- **#336 — Hide total notes status when the top bar shrinks.** Pure CSS — wrap the `9,007 notes 1,013 authors …` line in a `@media` query that `display: none`s it below some viewport width.

- **Pi MongoDB is on EOL 4.4.8.** Pinned in `docker-compose.yml`. MongoDB 4.4 EOL'd in Feb 2024; no upstream security patches. App works fine — not blocking — but worth upgrading in a maintenance window. **Use dump/restore (mongodump + mongorestore), not the in-place FCV version walk.** Concretely: with the old container running, `docker exec commonplace-mongo-1 mongodump --out=/data/db/dump-pre-upgrade`; `docker-compose down`; reset the `mongo-data` volume; bump image to `mongo:7.0` (LTS through July 2027) in docker-compose.yml; `docker-compose up -d`; `docker exec commonplace-mongo-1 mongorestore /data/db/dump-pre-upgrade`. Cost: brief downtime + doubled disk during transfer. **Critical rule:** never start a binary against data more than one major version older — doing so rewrites WiredTiger checkpoints into a format the older binaries can no longer read, locking you between FCV-too-old and WT-too-new. Dump/restore sidesteps this entirely because BSON is version-portable.
